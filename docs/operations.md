# Operations

Set `DATABASE_URL` for all binaries. `API_BIND` defaults to `127.0.0.1:3000`. `WORKER_CONCURRENCY` defaults to 4 and accepts values from 1 to 64. Set `RUST_LOG=chatflow=info,api=info,worker=info` to include spans from both binaries and shared runtime modules. All binaries apply SQLx migrations at startup.

For local development, start Postgres with `docker compose up -d postgres`, load `.env.example` values into the shell, then run `cargo run --bin api` and `cargo run --bin worker` in separate terminals. Run `scripts/local-bootstrap.sh TENANT_NAME` to create a tenant and separate application, RAGFlow configuration, and Prometheus keys. It stores them in ignored `.local/api-key`, `.local/rag-config-key`, and `.local/ops-api-key`. The database stores only their digests. Protect these local files. Issue the `rag:configure` key only after verifying that its tenant owns the intended RAGFlow datasets.

## Containerized local API and worker

For a complete local environment from empty volumes, run:

```sh
scripts/full-compose.sh up
scripts/full-compose.sh verify
```

`up` starts the pinned upstream RAGFlow CPU stack, waits for its storage and embedding services, creates a new RAGFlow API key and `chatflow-local` dataset with the official built-in `BAAI/bge-small-en-v1.5` embedding model, uploads and parses a smoke document, and confirms retrieval. It then builds the Chatflow image, applies migrations, creates a tenant and scoped keys, binds that dataset to the tenant, and verifies both a mock turn and a RAGFlow-backed turn. Generated secrets and IDs are written with mode 0600 under ignored `.local/`. No host Rust or Git toolchain is needed; Docker Compose, curl, Bash, and Python 3 are needed. The pinned upstream Docker configuration is included under `third_party/ragflow`, so a new checkout does not need to clone RAGFlow. Docker still needs registry access to pull uncached images, and the Rust image build needs access to crates.io. The admin bootstrap password comes from the pinned RAGFlow container's local `.env`; change it for any shared deployment.

`scripts/full-compose.sh down` stops both projects while preserving data. `scripts/full-compose.sh reset` removes both projects' containers and named volumes and deletes generated local keys and dataset IDs. **Reset deletes local RAGFlow documents and Chatflow data.** A subsequent `up` recreates and verifies the full environment, including a newly indexed RAGFlow dataset. This sequence was tested in a separate Compose project twice, including the RAGFlow volume wipe and a complete Chatflow RAG run. [The rebuild record](../benchmarks/2026-09-29-full-compose-rebuild.json) captures the checks. The script is for local development; provider keys kept in ephemeral Vault must be restored separately if you intend to use a live model after reset.

Run `scripts/compose-environment.sh up [TENANT_NAME]` to start the Compose app and supporting services from an empty state. It starts healthy Postgres and Vault, builds the non-root image, runs the bootstrap binary in a one-off container to apply migrations and create a tenant, saves scoped keys in ignored `.local/`, and starts the API, worker, and dashboards. `scripts/compose-environment.sh verify` publishes a mock flow and waits for a worker-completed run. `scripts/compose-environment.sh down` stops containers while preserving volumes; `scripts/compose-environment.sh reset` removes containers and named volumes and deletes the generated Chatflow keys. A subsequent `up` creates new tenant and keys. Each `up` creates a new tenant and replaces the generated key files; use `up` for provisioning or recreation, not as a routine restart command. The script requires Docker Compose, curl, and Python 3 on the host; Rust is built inside the image.

The script accepts `CHATFLOW_COMPOSE_PROJECT` and `CHATFLOW_STATE_DIR` to keep a rebuild check separate from the main environment. Set `CHATFLOW_COMPOSE_ENV_FILE` to an ignored environment file for router settings, and override the `CHATFLOW_*_PORT` variables in `docker-compose.yml` when running another project concurrently. For example:

```sh
CHATFLOW_COMPOSE_PROJECT=chatflow-check CHATFLOW_STATE_DIR=.local/chatflow-check \
  CHATFLOW_API_PORT=13000 CHATFLOW_POSTGRES_PORT=15432 CHATFLOW_VAULT_PORT=18200 \
  CHATFLOW_OTLP_GRPC_PORT=14318 CHATFLOW_OTLP_HTTP_PORT=14319 \
  CHATFLOW_OTEL_METRICS_PORT=19464 CHATFLOW_JAEGER_PORT=16687 \
  CHATFLOW_PROMETHEUS_PORT=19090 CHATFLOW_GRAFANA_PORT=13001 \
  scripts/compose-environment.sh up rebuild-check
```

Use the same variables for `verify` and `reset`. A blank RAGFlow key file is created when no key is configured so basic and mock flows can run. `scripts/ragflow-bootstrap.sh` separately provisions the pinned official RAGFlow stack, its admin API key, embedding dataset, and parsed smoke document. Set `RAGFLOW_PROVISION_STATE_DIR` to the same directory as `CHATFLOW_STATE_DIR`; the Chatflow `up` command then binds its dataset automatically and `verify` checks a RAGFlow-backed turn. `RAGFLOW_COMPOSE_PROJECT` and the `RAGFLOW_*_PORT` variables in the override file allow an isolated official RAGFlow project. Vault runs in dev mode and loses provider secrets when its container is recreated; restore the provider key and tenant credential after a reset before running a live model.

The optional Compose `app` profile builds both binaries into one non-root image. Stop any host-run API and worker before starting the containers, so port 3000 and run claims are not shared accidentally. Start RAGFlow with `scripts/local-ragflow.sh` and create `.local/ragflow-api-key` before starting this profile. Compose mounts that file as a read-only secret; it is excluded from the image build context. API and worker reach RAGFlow at `http://ragflow-cpu:9380` over the named `chatflow-ragflow-link` Docker network, including on native Linux where a service bound only to host loopback would be unreachable through `host.docker.internal`. `CHATFLOW_RAGFLOW_NETWORK` changes the network name for isolated projects. The profile sets `CHATFLOW_LOCAL_DOCKER_HTTP=true` to permit plain HTTP only to the explicitly named local services; other non-loopback HTTP endpoints remain rejected. Image builds default to Docker host networking to fetch Rust dependencies; set `CHATFLOW_BUILD_NETWORK=default` where ordinary builder networking works better. Running services use Compose networks.

Set `OPENAI_BASE_URL`, `OPENAI_MODEL`, and both `MODEL_*_USD_PER_MILLION` values in an ignored Compose environment file if you will run the router-backed flow. Set `VAULT_DEV_ROOT_TOKEN_ID` there as well if the local Vault dev token was changed. The API and worker use the Compose service names for Postgres, Vault, and OpenTelemetry. For example, with those values in `.env`:

```sh
docker compose --profile app config --quiet
docker compose --profile app up -d --build chatflow-api chatflow-worker
curl -fsS http://127.0.0.1:3000/health/ready
```

This workspace's tested local values are in ignored `.local/app-compose.env`; pass `--env-file .local/app-compose.env` immediately after `docker compose` for every command above. That file contains a local Vault token and synthetic model rates, so keep its permissions restricted and do not use it as a production configuration.

Use `docker compose --profile app stop chatflow-api chatflow-worker` to stop only the application containers. This profile is a local deployment path: the included Vault runs in ephemeral dev mode, Postgres has example credentials, and model admission rates must be replaced with contracted rates before production use.

## Moving the setup to another machine

Copy the repository, including all of `third_party/ragflow` and its `docker/.env.example` template, to a machine with Docker Engine or Docker Desktop and Docker Compose [**2.24.4 or newer**](https://docs.docker.com/reference/compose-file/merge/#replace-value), Bash, Python 3, and curl. The version requirement comes from the `!override` syntax in the RAGFlow Compose override. Do not copy `.local/`, `target/`, the local RAGFlow `docker/.env`, or Docker volumes for a fresh setup. From the new checkout, run `scripts/full-compose.sh up`; the startup script creates `docker/.env` from the template, and the setup creates new local keys, databases, a RAGFlow dataset, and a parsed smoke document. The command finishes only after both mock and RAGFlow-backed turns pass. Use `scripts/full-compose.sh down` to stop it and `scripts/full-compose.sh reset` only when you intend to delete its local data. The API binds to `http://127.0.0.1:3000`, RAGFlow's UI to `http://127.0.0.1:18080`, and RAGFlow's API to `http://127.0.0.1:9380` by default.

The first run needs access to container registries for the pinned images and to crates.io during the Rust image build. All published service ports bind to the host's loopback interface. Chatflow and RAGFlow communicate across a named Docker network instead of a host loopback port, so the same Compose files work with Docker Desktop and native Linux networking. Set `CHATFLOW_BUILD_NETWORK=default` if the target builder cannot use host networking. Set the `CHATFLOW_*_PORT` and `RAGFLOW_*_PORT` overrides if those host ports are in use. The clean-copy test from another filesystem location passed with empty local state and named volumes on macOS; a separate native Linux host has not been exercised. Existing documents, tenant data, and live provider credentials are not transferred by this fresh setup. Back up and migrate them separately when you need the same data or live model access.

[The container smoke record](../benchmarks/2026-09-29-container-rag.json) confirms that the non-root API and worker started, the API passed readiness, the worker read the mounted RAGFlow key, the collector exposed run metrics, and a complete RAGFlow-to-Claude-Haiku turn succeeded with source IDs and reported usage.

Use `POST /v1/api-keys/rotate` with a `keys:write` token to issue a replacement. Store the returned secret immediately; the API will not return it again. Verify the new token, then revoke the old token by its public ID. Both tokens share one quota record, and a parent-key revocation disables all of them. The local RAGFlow configuration and Prometheus keys have no `keys:write` scope; replace them through trusted operator provisioning if needed.

Run `docker compose --profile app up -d otel-collector prometheus grafana chatflow-api` to start the local observability stack with a containerized API. Set `OTEL_EXPORTER_OTLP_ENDPOINT=http://127.0.0.1:14317` on a host-run API or worker to export structural traces and run counters. The collector receives OTLP gRPC on host port 14317 and OTLP HTTP on 4318; it forwards traces to Jaeger and exposes converted OpenTelemetry metrics on 9464. Jaeger's trace UI is at `http://127.0.0.1:16686`, Prometheus is at `http://127.0.0.1:9090`, and Grafana is at `http://127.0.0.1:3001`. Grafana provisions the Prometheus data source and the Chatflow dashboard. The example Grafana password is for local use only; override `GRAFANA_ADMIN_PASSWORD` before starting its container. Prometheus scrapes `chatflow-api:3000` inside the Compose network using the generated ops key. All published Compose ports bind to loopback.

The worker claims `interactive` jobs with a 20-second lease and refreshes it every five seconds. Multiple worker processes may share the queue. A process runs at most `WORKER_CONCURRENCY` jobs at once. Expired leases can be reclaimed up to each job's claim limit; exhausted jobs are marked failed. Completed node checkpoints are reused after a reclaim. An interrupted `llm.chat` call needs an explicit node retry budget because its prior provider outcome may be unknown. The worker uses `mock` by default. For `openai`, set `OPENAI_MODEL`, `VAULT_ADDR`, and `VAULT_TOKEN` on workers only. `OPENAI_BASE_URL` optionally selects a server-configured OpenAI-compatible endpoint; it defaults to `https://api.openai.com/v1`, requires HTTPS or loopback HTTP, and uses the Chat Completions streaming API. The worker reads `api_key` from Vault KV v2 at `secret/data/<secret_reference>` for the tenant-owned credential ID in the flow. The API never receives a Vault token or the provider base URL.

For local development, `docker compose up -d vault` starts an ephemeral Vault dev server at `http://127.0.0.1:8200`. Its default root token is `local-dev-only`; override `VAULT_DEV_ROOT_TOKEN_ID` before startup if needed. Write an OpenAI key with `VAULT_ADDR=http://127.0.0.1:8200 VAULT_TOKEN=local-dev-only vault kv put secret/tenants/TENANT_UUID/openai api_key=YOUR_KEY` using a local Vault CLI. Register `tenants/TENANT_UUID/openai` with `POST /v1/provider-credentials` using `credentials:write`, then use its returned `credential_id` in an `openai` node. A reference must start with the calling tenant's `tenants/<UUID>/` prefix and contain only ASCII letters, numbers, `_`, `-`, and `/`. The worker checks that prefix again before reading Vault. The dev Vault loses stored keys on container recreation; production needs a persistent Vault deployment and a narrowly scoped worker token.

The tested OpenAI-compatible router uses `OPENAI_BASE_URL=https://llmrouterv2.aevai-health.com/openai` and `OPENAI_MODEL=bedrock/eu.anthropic.claude-haiku-4-5-20251001-v1:0` on workers. Its catalog also lists the unprefixed Haiku ID, but that ID returned a Bedrock inference-profile error; use the working `eu.` profile ID. Keep the router API key in the tenant's Vault path and use the `openai` flow alias with its registered `credential_id`. A local live RAGFlow-to-Haiku run succeeded after the credential was registered through `POST /v1/provider-credentials`; its temporary scoped management key was revoked. Local synthetic admission rates used for that smoke test are not provider prices and must be replaced with contracted rates before production use.

RAG uses an existing [RAGFlow deployment](https://ragflow.io/docs/dev/http_api_reference). Upload, parse, update, and reindex documents in RAGFlow. Set `RAGFLOW_BASE_URL` and either `RAGFLOW_API_KEY` or `RAGFLOW_API_KEY_FILE` on API and worker processes. The file setting takes precedence and keeps the secret out of process command lines; restrict the file to the service user. Use `PUT /v1/ragflow-datasets` with a `rag:configure` application key to bind each tenant to RAGFlow dataset IDs. The mapping is stored in Postgres and takes effect on the next retrieval. HTTPS is required except for `localhost` or `127.0.0.1` HTTP. A RAGFlow API key must be able to retrieve from those datasets; store it only in server configuration. `rag.retrieve` sends a question and the mapped dataset IDs to RAGFlow's `/api/v1/retrieval` endpoint. It rejects chunks from any dataset outside that mapping. RAGFlow handles document parsing, embeddings, indexing, and version management.

For a local RAGFlow instance, run `scripts/ragflow-bootstrap.sh` to start and provision it, or `scripts/local-ragflow.sh` to manage the upstream containers without provisioning. Both use the pinned official RAGFlow v0.27.2 Docker files in tracked `third_party/ragflow`, its CPU profile and dependencies, and the official CPU embedding service with `BAAI/bge-small-en-v1.5`. Its web UI is on `http://127.0.0.1:18080` and its API is on `http://127.0.0.1:9380`. The embedding service's host port 6380 binds to loopback; RAGFlow connects to it on the Compose network at `http://tei:80`. The bootstrap script writes the API key and dataset ID under the selected state directory; the Chatflow setup script assigns that dataset to its new tenant. On Apple Silicon, the upstream RAGFlow and TEI images run under amd64 emulation and startup can take longer. Stop the stack with `scripts/local-ragflow.sh stop`; remove its volumes only through the explicit full reset command.

Run events and token chunks are currently durable in Postgres. Monitor database growth before increasing traffic. Run admission and rolling daily input-token, output-token, and estimated-spend reservations are stored on tenants and API keys. Configure both `MODEL_INPUT_USD_PER_MILLION` and `MODEL_OUTPUT_USD_PER_MILLION` on the API before admitting `openai` transport runs, including Bedrock models; production prices must reflect your contract. The legacy `OPENAI_*` pair is accepted only when neither `MODEL_*` value is set. A deliberately high local test value is only a conservative admission ceiling and makes the displayed cost estimate inaccurate.

Retention is disabled by default. Set `message_retention_days` and `run_retention_days` independently on a tenant to values from 1 to 3650; `NULL` keeps that category indefinitely. For example, `UPDATE tenants SET message_retention_days = 30, run_retention_days = 90 WHERE id = '<tenant UUID>';`. Workers sweep every hour by default; `RETENTION_SWEEP_SECONDS` accepts 60 to 86400. A sweep deletes old messages and only finished runs older than their configured limit, including each run's events, node checkpoints, and job. Active runs and other tenants' data remain. Each sweep is bounded to 100 runs and 500 messages; a full batch triggers another sweep shortly afterward.

## Metrics and alerts

`GET /v1/ops/metrics` requires an `ops:read` key and returns Prometheus text for that key's tenant. The local Prometheus configuration reads that key from `.local/ops-api-key`; do not put it in dashboard JSON. [The Grafana dashboard](../ops/grafana-dashboard.json) and [the Prometheus alert rules](../ops/prometheus-alerts.yml) are loaded automatically by Compose. The panels show interactive backlog, oldest queued run, model failures, provider throttling, and recent token usage. Set the `MODEL_*_USD_PER_MILLION` pair on the API to add an estimated model cost metric; the metric is absent until prices are configured. Use your contracted rates. Cost is based on reported token usage from the `openai` transport alias and is an estimate. Alert thresholds in the rules file are starting values to tune for the deployment.
