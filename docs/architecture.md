# Architecture

The API authenticates application keys, validates and publishes flow versions, creates runs, and serves run status, messages, and SSE events. Workers claim queued runs from Postgres with `FOR UPDATE SKIP LOCKED`, execute registered Rust node handlers, checkpoint node outputs, and append ordered events.

A run points to one immutable `flow_versions` row. The `runs.next_event_sequence` counter assigns each event a monotonic sequence within its run. SSE clients can reconnect with `Last-Event-ID`; the API reads later events from Postgres. User and final assistant messages are stored in `messages`.

Each conversation records its owning API key ID. API reads and new turns require that key ID as well as the tenant ID; rotated tokens retain the same owner. `conversation_variables` stores JSON values under `(tenant_id, conversation_id, name)`. The API controls direct reads and writes, while reviewed `variable.get` and `variable.set` nodes access string values for the run's own conversation. Writes lock the conversation row to enforce the per-conversation count limit under concurrent requests.

The worker resolves model aliases from its server configuration. The `mock` alias is deterministic; `openai` uses Rig's Chat Completions adapter and requires `OPENAI_MODEL` plus a tenant-owned credential ID in the flow. An optional `OPENAI_BASE_URL` selects a trusted OpenAI-compatible router. The worker alone resolves the credential ID to a Vault KV v2 reference and reads the provider key. Flow JSON has no provider URL or secret.

The runtime executes independent ready nodes concurrently up to each flow's `max_parallel_nodes` limit and checkpoints every completion. Condition guards skip inactive branches; `select` joins the chosen result. Workers resume from completed or skipped checkpoints after an expired lease. An interrupted model call is retried only when its node declares a retry budget; otherwise the run fails to avoid repeating an ambiguous provider call. Transient model failures and timeouts use bounded retries. Cancellation changes both the run and job status in one transaction; the worker checks lease ownership before committing output. The `interactive` queue handles chat turns. RAGFlow owns document ingestion, parsing, embeddings, indexing, and retrieval. The worker's `rag.retrieve` adapter calls RAGFlow with an operator-owned API key and tenant-specific dataset IDs stored in Postgres. Only trusted operator keys should receive `rag:configure` to assign those IDs. The run timeline retains returned dataset, document, and chunk IDs.

When `OTEL_EXPORTER_OTLP_ENDPOINT` is configured, API and worker tracing spans and run counters go to an OpenTelemetry Collector. The local collector sends traces to Jaeger and exposes metrics for Prometheus. Span fields contain structural IDs and node types, not flow input, prompts, responses, or provider credentials.
